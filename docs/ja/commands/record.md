## B 系スコア画像

| コマンド | 動作 |
|---|---|
| `b50` / `best50` | 旧曲 35 + 新曲 15 |
| `b40` / `best40` | 旧曲 25 + 新曲 15、旧 Rating 計算 |
| `b35` / `best35` | 旧曲 Best 35 |
| `b15` / `best15` | 新曲 Best 15 |
| `ab35` / `allb35` / `ab50` / `allb50` | 新旧を分けず上位 35 / 50 |
| `apb50` / `ap50` | AP/AP+ の旧曲 35 + 新曲 15 |
| `fdxb50` / `fdx50` | FDX/FDX+ の旧曲 35 + 新曲 15 |
| `rct50` / `r50` | 保存済み Recent、元の順序を維持 |
| `idealb50` / `idlb50` | 達成率を上げた仮想 B50。保存データは変更しません |
| `s50` / `sun50` / `寸50` / `寸止め` | SSS/SSS+ に近い 50 件 |

## フィルター

```text
b50 -lv 14 14.9 -diff mas rem -scr 100.5
ab50 -ver buddies prism+ -type dx
b50 -dx
b50 -star 5
b50 -page 2 -times 2
```

| パラメータ | 動作 |
|---|---|
| `-lv` / `-level` | レベル・定数。`14`、`14+`、`14.7`。2 値は範囲 |
| `-ra` / `-rating` | 1 値は単曲 Rating 完全一致、2 値は両端を含む範囲 |
| `-scr` / `-score` | 1 値は達成率下限、2 値は両端を含む範囲 |
| `-dx` / `-dxscore` | 値なしで DX スコア比率順。整数百分率 1 値は下限、2 値は範囲 |
| `-star` / `-dxstar` | DX 星数の完全一致または 2 値の範囲 |
| `-diff` / `-difficulty` | `bas adv exp mas rem` または正式難易度名、複数指定可 |
| `-type` / `-tp` | `dx`、`std`、複数指定可 |
| `-ver` / `-version` | バージョン名完全一致、複数可。PLUS は `+`、例：`buddies prism+` |
| `-next` / `-nxt` | 現データの最後のバージョンで新旧区分を変更。将来の定数予測ではありません |
| `-page` / `-pg` | 1 ページから。新旧それぞれをページ分割 |
| `-times` / `-tm` | 件数倍率、最大 2.5、5 件単位で切り上げ。画像の拡大率ではありません |

既定では単曲 Rating、達成率の降順で選択します。フィルター後の件数が少ない場合は補充しません。

`r50` は保存済み Recent を使います。フィルターは適用されますが、`-page` と `-times` によるページ分割・件数拡大、および `-dx` による並べ替えは行いません。

`寸50` は `100.4000%–100.4999%` と `99.9000%–99.9999%` のみを対象に、目標との差が小さい順、定数が高い順に選択し、SSS+ と SSS に分けて表示します。

理想モードは 99–99.5、99.5–100、100–100.5、100.5–101 の区間をそれぞれ 99.5、100、100.5、101 に引き上げて計算します。99 未満は変更しません。実際の記録ではなく目標シミュレーションです。

## 楽曲・リスト・進捗

```text
ヒバナ record
13 records
14.7 records 2
13+ levels
13sss+ prog
14ss+ prog -uc
vocaloid ap prog -up
真極 plate
真極 plate -c
PRiSM PLUS ver
```

`record` は曲名・別名 で保存済み成績を検索し、複数候補なら選択リストを返します。`records` は個人成績一覧でページ指定に対応。`levels` は譜面一覧で、このページ接尾辞には対応しません。

`prog`・`levels` はレベル `11`、`11+`、`12`、`12+`、`13`、`13+`、`14`、`14+`、`15` に対応し、小数定数は非対応です。ここでの `14+` は 15 も含みます。カテゴリ `vocaloid`、`popani`、`touhou`、`gekichu`、`game`、`maimai` に対応。目標は `s`、`s+`、`ss`、`ss+`、`sss`、`sss+`、`fc`、`fc+`、`ap`、`ap+`、`fdx`、`fdx+` です。

`prog`・`plate` の末尾に `-uc`（未達成）、`-up`（未プレイ）、`-c`（達成済み）を指定できます。プレート種別は `極`、`将`、`神`、`舞舞`。対象バージョンはサーバー別曲庫に従います。

## フレンドとメンション

```text
friends
friend-rcd <friend_code> b50 -lv 14+
@friend b50
@friend 13 records
@friend 14sss+ prog
```

`friends` / `friend list` と `friend-rcd` は個別チャット・完全な SEGA 連携が必要で、maimai NET からフレンド情報を取得します。メンションは対象者の JiETNG 保存済みデータを使う別の機能です。

メンション対応は B 系、`record`、`records`、`prog`、`plate`、`rank`。対象者の登録・成績データ・検索許可が必要です。対象が無効でも自分の成績には戻りません。`levels` は本人のデータを使い、本人専用のアカウント操作で他人をメンションすると拒否されます。

## 画像認識と判定分析

リザルト画像を送信し、LINE の「返信」でその画像を引用して送ります。

- `rec`：曲名・達成率・判定を認識・検証し、通常は分析画像を返します。有効な候補が複数ある場合は複数画像になることがあります。
- `rec -flex`：確認・修正向けの対話カードを返します。
- `crop`：認識領域の切り抜きプレビュー。
- `info`：引用画像から曲名を読み取り、楽曲情報を検索。

可能な限りメイン画面とサブ画面の判定表を含めてください。不足や矛盾があると失敗または手動修正になります。認識結果は Best/Recent に取り込まれません。

### 手動修正

Bot の `fix-rcd` 修正テンプレートを使います。全 7 行で、1 行目は `fix-rcd 曲名`、2 行目は達成率（0–101、小数 4 桁まで）。続く 5 行は TAP、HOLD、SLIDE、TOUCH、BREAK の順で、各行に `CRITICAL PERFECT/PERFECT/GREAT/GOOD/MISS` の非負整数 5 個を `/` 区切りで記入します。

改行を維持し、説明文は含めないでください。修正後も物量・達成率検証が必要で、保存済みのプレイ記録は書き換えません。
